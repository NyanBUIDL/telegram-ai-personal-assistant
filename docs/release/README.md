# Release content and rights gates

Public release is blocked by the explicit inputs in [release-gates.json](release-gates.json). The project remains private-use; no new LICENSE or source redistribution grant is created. The current source hygiene was already performed by coordinator commit `81a40535`, without rewriting history. Local source checks, a directory package, and dependency metadata cannot substitute for owner authorization or an actual Windows artifact review.

Run `python scripts/check-release-content.py` for the tracked **index** content and preserved asset hashes. It ignores untracked/private runtime files and does not load application settings or credentials. Exit 0 means no unclassified finding in that bounded audit, not secret-free history or release approval. Exit 1 means findings; exit 2 means incomplete audit. Add `--public` to require asset rights and all release gates; public mode intentionally remains nonzero. `--no-assets` is content-only and cannot approve release.

To audit history, pass an explicit ancestor commit to `--history-base` and an immutable `--history-head`. The base snapshot plus changed source blobs through that head are scanned. The output records the exact bounds, roots, excluded generated/binary content and scanned blob count. Historical `.env` blobs are inspected only as bytes by the masked scanner; no Settings/SecretStore/key validation/network use occurs. Reports expose only paths, commits, kinds and SHA256 hashes of candidates. The current live `.env`, session stores and untracked credentials are never read. Unknown candidates require owner-context review and rotation if actually used. The tool cannot prove absence of credentials outside its patterns/roots or in generated/binary/excluded history.

[Secret dispositions](secret-scan-dispositions.json) classify exact path+kind+hash test fixtures and disposable CI credentials. A test directory or a word such as "test" alone never suppresses a finding. Historical `.env` exposure is retained even if a candidate later proves synthetic. No scanner command revokes keys, contacts providers, sends messages, rewrites history or alters Git state.

[assets-manifest.json](assets-manifest.json) preserves both original font and reference-image hashes. DarleySans needs font-specific rights for the LyonsType OTF and resolution of the related OFL author's attribution discrepancy. LNTH-Peter needs the derivative's upstream notice/modification provenance and reserved-name compliance. Keep the reference out of the shipped runtime unless public rights are separately established.

The [CycloneDX source inventory](dependency-inventory.cdx.json) is a development/source dependency inventory, not an artifact SBOM. Resolve its 37 unknown license records against actual selected distributions, inventory bundled Qt DLLs/plugins and Python native dependencies, and supply complete required notices before distribution. Regenerate after storage/packaging tasks update dependencies. The original `pyproject.toml` and npm lock hashes in the inventory identify its source inputs; broad requirement ranges are not a release lock.

The intended LGPL approach is a dynamic directory package with replaceable PySide/Shiboken/Qt libraries. This is an inference from [Qt's official obligations](https://www.qt.io/development/open-source-lgpl-obligations), not verified artifact compliance. Packaging must provide the actual relevant LGPL/GPL texts, library source or compliant written source offer, prominent notice, source/version/build provenance, installation information and a demonstrated replacement/relink route; recipient rights cannot be restricted by an EULA or signing/packaging controls. Validate each shipped module under its own applicable license using [Qt's licensing inventory](https://doc.qt.io/qt-6/licensing.html) and [Qt for Python's third-party notices](https://doc.qt.io/qtforpython-6/licenses.html). No QtWebEngine or GPL-only add-on is introduced by R01.

The proposed Inno installer has a permissive commercial-use basis in its [official license](https://jrsoftware.org/files/is/license.txt). The [commercial support request](https://jrsoftware.org/isdl.php) is distinct from a mandatory purchase condition. Preserve the selected tool's notices and version-specific license; no purchase is performed.

Suggested ignore additions for QA/coordinator review: `.mypy_cache/` and `tests/testdata/` if a future runtime fixture directory is introduced. Existing `.venv`, `.venv-q01`, node_modules, caches, CI work/artifacts, `.env`, sessions, databases, logs and release build output are already ignored. R01 does not edit the QA-owned `.gitignore`.
